# Codex Sleep State 0.5.1

Sub2API 的 OpenAI OAuth 保护传输插件。内嵌上游 `b18fabf` 的网关与状态机核心，执行 `X-Codex-Turn-State` 采集、缓存、注入和响应检查，同时支持 HTTP/SOCKS 代理与 Mihomo 订阅。安装时上传 `.s2plugin`，首次安装按宿主提示信任原发布者 `local-account-protection-v1`，无需安装 Go、Node 或代理内核。

## 开启核心保护

0.5.1 修复了“收到 state 但形状不符 → 错误禁用正常代理 → Codex 连不上”的故障。升级时只恢复被旧版资格误判的节点，保留手动停用和真实网络失败。

1. 在「请求头保护」点击「一键启用保护」，并在宿主启用插件、绑定 OAuth 保护传输路由。
2. 选择自动、个人或团队账号规则；新配置默认拿到合格 state 后固定使用，也可选择主用与备用模式。
3. 让匹配的实际请求经过插件，再点击「刷新运行状态」，查看期望/观测长度、主备可用性、剩余时间、采集冷却与原因。
4. 如需重新采集，使用会话行的采集按钮。采集会发送短模型请求并消耗额度；普通节点连通性测试不会。

如需在没有合格 state 时继续使用 Codex，点击「允许无 state 时正常转发」。严格模式仍会拒绝没有合格 state 的请求，但现在作为明确的本地保护拒绝，不再被宿主当成上游 503 而轮换账号。首次同步采集整轮默认最多 20 秒，为正式转发留出时间。

## 验证订阅中哪些节点能取得 state

1. 保持宿主插件启用，让一次普通 OAuth 请求经过插件，随后刷新运行状态。无需开启注入，也不需要复制凭据。
2. 在「逐节点验证 X-Codex-Turn-State」选择对应账号/模型会话，点击「验证全部节点的 state」，或选择单个节点验证。
3. 查看每个节点是否返回头、是否可解析、实测字符/块数、目标字符/块数、是否合格和 HTTP 状态。格式不匹配与连接失败分别展示。
4. 验证默认每轮最多 6 次，轮间冷却，自动继续剩余节点；可取消。401/403/429 或明确上游失败会暂停，不继续换出口尝试。

这是实际模型短请求，最多对每个选中节点发起一次，可能消耗额度。纯验证不改变正在使用的 state 或出口；找到合格节点后，可在来源列表选择它。验证结果不代表不同节点拥有不同公网 IP，也不证明模型质量。

采集默认每轮最多 6 个出口、全进程串行，并保留冷却与 401/403/429 暂停。state 按宿主账号、OAuth 凭据、工作区和模型隔离。上游返回不符合规则的 state 时拦截正文，备用供下一条请求使用；已经发送的正式请求不会由插件重放。

核心同时包含 gzip/zstd、有界大请求、V1/V2 远程压缩、独立正式出口，以及可用/已用/失败/停用节点池。详细请求头与适配边界见 [核心封装说明](docs/CORE.md)。

## 配置与节点管理

1. 打开「配置 → 来源与节点」。代理每行一个 URL；订阅每行一个完整 HTTPS 链接。
2. 点击「保存并获取节点」。节点表会显示名称、协议和稳定 ID。
3. 点击「测试全部连通性」或单行「测试连通性」。它只检查网络，不能证明已取得合格 state。
4. 点击「使用此节点」保存固定出口，或选「自动轮换」并保存。

HTTP/HTTPS 支持用户名密码；保留 URL 编码的特殊字符。`127.0.0.1` 指 Sub2API 内核所在机器，远程和容器部署应使用内核能访问的代理地址。环境变量也必须位于插件进程环境中，宿主不自动继承终端环境。

节点获取/测试的结果通过宿主现有配置桥接保存，插件停用时也可测试、选节点和重新打开查看。单次诊断最多 12 秒；测试未完成与失败分别展示。403/429 表示网络已到达目标但访问受限制，不代表代理断线，也不证明该账号能发模型请求。

配置加载失败时禁止覆盖保存，先使用宿主的配置恢复功能。不会默默清空旧配置。

## 功能与范围

- HTTP、HTTPS、SOCKS5、SOCKS5H，以及 Mihomo v1.19.31 支持的 VLESS、VMess、SS、SSR、Trojan、AnyTLS、Hysteria、Hysteria2、TUIC。
- HTTPS/回环 HTTP 订阅、文件及环境变量来源，YAML/URI/Base64 解析，最多 256 节点。
- 默认由产生 state 的路由转发；也可明确选择独立随机或固定出口。
- 订阅默认在下次请求到来时按 900 秒周期刷新；刷新失败保留旧池，连接失败后在后续请求重建；不重放已发送生成请求。
- OAuth/process 模式。无需修改 Codex 配置；不启动本地管理服务，不处理 API Key/relay。

节点生命周期持久化到宿主安装目录中该插件 ID 下的 `.state/routepool.json`，仅含节点 ID 和生命周期，不保存凭据或 state。不同宿主节点的记录互不共享。详见 [安装说明](docs/INSTALL.md)、[验证范围](docs/VERIFICATION.md)。三平台签名包使用同一发布者身份；包 SHA-256 在旁置 `.sha256` 文件中。

## 开发验证

在插件目录执行 `go test ./...`、`go vet ./...`。`scripts/test-ui.py` 检查界面交互；真实宿主签名包测试入口是 `backend/internal/handler/admin/ccodex_plugin_ui_flow_test.go`，覆盖获取节点、测试、选择和重开。

实际成功转发的签名包验收是 `backend/internal/service/ccodex_sleep_state_signed_proxy_test.go`：安装后的真实进程通过 CONNECT 代理访问 TLS/SSE 测试上游，覆盖取得并注入合格 state、错形状兼容转发、严格本地拒绝与配置允许的新模型。该测试使用合成凭据和本地测试证书，不调用用户账号。

构建中间文件写入 `.build/`，验收成功后再移入 `dist/`。`dist/` 只保留本次分享包、SHA-256、公钥和发布者信任示例。
