# Sub2API Cost Console v0.2.38

## 主要更新

- 修复重复确认同一终局故障后，已退款费用被重新计入的问题。
- 修复 API Key、Service Account、中转等按量账号的自定义固定附加费在后端经济总成本中遗漏的问题。
- 修复“当天”费用混入昨天或未来时段的问题；前后端使用明确的起止时间与客户端时区。
- 按量账号未配置固定附加费时，不再因套餐标记而套用订阅默认价。
- 成本档案尚未到起算时间时，累计费用和当前小时费率均为零。
- 成本中心原“Sub2API 设置”入口改为“账号管理”，直接进入账号列表。
- 保留 Docker 恢复、受管内核双槽回滚、成本账本、经济采样及 Windows 原生一键启动。

## 当前兼容内核

- 上游 Sub2API：`v0.2.5`
- 上游提交：`86f93c28ee34cc74b629dafb748bd5ac5ca8c5ea`
- 成本扩展：`v1.1.2`
- 成本算法：`v1.6.1`
- 必需能力：`account_cost_loss_ledger.v1`、`account_economics_sampling.v1`

## 技术变更

- 终局、退款与恢复操作按账号使用 PostgreSQL 事务锁串行化；默认终局键使用持久化恢复事件边界，不再使用账号 updated_at。
- 同一未恢复生命周期复用原始终局；兼容读取旧重复有效终局时保留首次冻结时间并合计各笔退款。恢复时原子关闭该生命周期内的全部有效终局。
- 自定义固定费、默认订阅价和终局损失资格分别判断，保留原有按量调用成本公式。
- 经济快照支持 start_time、end_time、timezone；已发生成本截止到观察时间，并正确处理午夜、夏令时和本地月份边界。
- 前后端共用一份金额样例进行一致性验证；原审计失败用例纳入默认回归测试。

## 升级行为

- 内核更新可修复服务端终局账本和固定附加费聚合；时间窗口参数、前端默认价、未来费率与账号入口修改需要配套桌面版本。
- 本次无需数据库结构迁移，不修改原始 usage_logs、成本档案或既有损失事件。恢复仍以追加冲销事件记录。
- 算法版本升至 1.6.1，成本扩展升至 1.1.2；既有档案与历史事件的版本字段继续保留。
- 上游 Token 价格、730 小时/月折算规则和汇率来源保持不变。

## 验证结果

- 回归覆盖重复终局与退款、不同账号类型固定附加费、自然日和未来时间边界。
- 真实 PostgreSQL 并发测试覆盖重复确认、退款余额、恢复后再次终局，以及旧重复事件的合并读取与恢复。
- Web/桌面构建、前端全量、Go 与 Rust 检查结果记录于 `docs/2026-09-16_cost-algorithm-extension-audit-report.md`。

## 回滚说明

- 没有新增数据库迁移；历史事件仍可追溯，未通过批量改写历史金额修复报表。
- 回退旧代码会重新暴露本次修复的成本口径问题。独立内核回滚不会替换桌面前端。
