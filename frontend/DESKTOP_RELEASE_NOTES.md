# Sub2API Cost Console v0.4.3

## 主要更新

- “补齐已确认模型”覆盖当前账号官方目录实际返回的全部模型，不再局限于内置的 8 个推荐模型。官方以后新增模型时，只要当前账号目录可见，即可获取并补齐到编辑草稿。
- 保留已有精确映射和末尾通配符规则；多个别名指向同一模型时，可以补齐该模型的原名入口，原别名继续保留。重复返回或重复补齐不会添加重复项。
- 补齐只修改当前草稿，需要保存账号后才生效。获取失败、账号或草稿变化时，旧结果不会继续用于补齐。
- 沿用 v0.4.2 的官方模型校对、GPT-6.1 Terra 支持及上游 Sub2API `v0.2.18` 基线，本轮没有新增上游合并。
- Windows 原生一键启动、插件协议和六项必需能力与上一版保持兼容。

## 技术变更

- 官方校对服务按实时目录中的全部 ID 生成缺失的同名映射，建议映射继续复制并保留原规则，不写入账号数据。推荐模型列表仍用于提示“官方未列出的推荐模型”，两者范围独立。
- 前端从本次官方返回的模型中去重生成补齐候选，并要求服务端建议为同名映射；不接受仅出现在建议中、未出现在本次官方目录中的模型。
- OAuth 和 API Key 账号均支持非预设模型补齐；白名单和映射编辑模式均保留保存前的草稿边界。
- 本轮只扩展目录补齐范围，不新增模型协议、推理档位、工具调用或计费适配。官方目录中的 ID 可能包含非文本模型；目录可见不等于已验证实际推理兼容。
- 插件协议、SDK、能力清单和应用身份保持兼容。宿主二进制变化使扩展版本递增，已发布的同名内核包不能用不同 SHA-256 覆盖。

## 升级行为

- 可在“版本与更新”中升级，也可以退出程序后使用安装器原位升级；已有账号不会在后台自动保存新增模型，需要在编辑页获取、补齐并保存。
- 本轮不新增数据库迁移。从 v0.4.0 或更早版本升级时仍会经过迁移 246/247；迁移 246 会将已有 Gemini/Antigravity 分组中关闭的 `allow_image_generation` 批量改为开启，降级不会自动恢复这些值，升级前应保留数据库备份。
- 桌面、兼容内核或扩展版本变化后的首次启动会停用旧插件一次，保留配置、已签名原包、发布者信任及路由作用域；确认兼容后重新启用。
- 兼容内核先于桌面安装器发布，校验版本、上游提交、扩展版本、能力清单和归档 SHA-256，并在发布后下载回读。
- 官方校对需要当前账号的有效凭据和可用网络。官方列表只反映该账号当前可见的模型，不保证所有账号可见同一组模型。

## 验证结果

- 功能开发阶段本地检查已通过：Go 1.27.3 下官方校对服务及管理员接口定向回归；前端 5 个 Vitest 文件共 95 项测试、类型检查和改动文件 ESLint。回归覆盖 OAuth/API Key、未来模型、精确映射、通配符、别名、去重、幂等和保存前不写入。
- 最终发布门禁要求同一源码 SHA 通过完整后端 unit、integration、golangci-lint、插件契约/生命周期/路由范围/V1/V2/race、完整前端测试与 lint、Rust 桌面测试及生产构建。最终状态以对应 GitHub Actions 执行记录为准。
- 当前功能尚未使用真实账号调用官方模型接口。生产插件 E2E 需要独立测试数据库及 Docker；不可用时必须记录跳过原因，不能据定向测试宣称生产插件链路已完整验证。
- 安装器、Tauri 更新签名、更新清单、稳定内核和开发包须在发布后重新下载，核对版本、能力及 SHA-256。

## 回滚说明

- 本轮可回退到桌面 v0.4.2 及匹配的内核 `v0.2.18` / 扩展 `1.3.21`。回退前备份数据库；跨越迁移 246/247 回到更早版本时，还需确认迁移兼容和数据补偿方案。
- 兼容内核稳定通道不允许降级发布，也不允许同名包更换内容。出现问题时向前修复并递增扩展版本；客户端可使用本地回滚槽位回到上一个内核。
- Tauri updater 的 `.sig` 用于自动更新验签，不代表 Windows Authenticode 发行者签名。
