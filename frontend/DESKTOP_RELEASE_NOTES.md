# Sub2API Cost Console v0.2.19 技术说明

## 内核基线

- 上游 Sub2API：`v0.1.173`
- 上游提交：`29009f0b2ea14edf3b11ae2564fb617ff91a03b4`
- 成本扩展：`v1.1.0`
- 成本算法：`v1.6.0`
- 经济预测与时间序列：`v1.1.0`
- 必需能力：`account_cost_loss_ledger.v1`、`account_economics_sampling.v1`

## 技术变更

- 修复 Apple 语义样式跟随 Windows 浅色外观时覆盖成本控制台的问题。成本扩展现在建立显式深色语义边界，所有工作区、内容面、工具栏、弹层、标签和控件统一恢复深色背景、浅色文字与 Sub2API 荧光绿强调色。
- 增加颜色合同回归测试，锁定主文字、次要文字、强调色和强调色前景的实际对比度，并防止成本内容面再次回退为白底黑字。
- 一级导航移除低频“数据治理”项目，治理功能保留并收进右上角工具区；资产总览、上游排行、渠道号池和 API 接入保持为四个主要工作区及 `Ctrl/Cmd + 1…4` 快捷入口。
- 新增后端持久化经济采样：相邻样本只在账号成员稳定、累计值未倒退时参与速率计算；样本不足时返回不可用，不再用“今日累计 ÷ 已过小时”伪造实时速率。
- 新增账号池单位经济性：API 产出与上游 Token 成本保持 USD，采购与封禁损失统一折算为 CNY，并输出每 1 USD 产出的采购成本、贡献结果、回本比例与预测置信度。
- 成本算法版本提升到 1.6.0，但 Sub2API 输入、输出、缓存 Token 公式、模型价格和采购摊销公式均未调价。
- 将账号封禁损失账本补丁合并到官方 Sub2API v0.1.173 基线，保留上游新增功能与修复。
- 内核身份拆分为上游版本、上游提交、扩展版本、能力集合和文件 SHA-256；桌面 Git 提交与构建时间不再参与兼容性判断。
- 新增候选内核能力握手。只有同时报告扩展版本、`account_cost_loss_ledger.v1` 和 `account_economics_sampling.v1` 的二进制才能进入待激活区。
- 修复 v0.2.17 会继续复用仅具备账本能力的 1.5 活动核心的问题；旧核心现在会在安全启动阶段切换为内置 1.6 核心。
- 修复多行 `CORE_CAPABILITIES` 写入 Cargo 构建环境时只保留第一行的问题，后续新增能力不会再被静默截断。
- 内核更新切换到独立 `core-stable` 通道，官方 Release 仅用于发现上游新版本，原版二进制不会直接覆盖成本扩展。
- 新增每 6 小时运行的上游同步流水线：无冲突且全部测试通过时自动构建并发布兼容内核；冲突或测试失败时停止发布并创建维护事项。
- 时间序列按观察窗口自适应为 5 秒至 6 小时桶；1/5 分钟事件窗口分别保留 12/20 个细粒度点，中长窗口约 30–120 点。运行趋势提供收入、上游成本、贡献、单位采购成本、回本/毛利率、请求结果、402/429、切号、TTFT、总耗时和 Token 结构。
- 经济采样响应新增账号健康序列与可证明事件标记；账号池成员变化、累计值倒退、采样中断、核心启动和封禁核销会在图表中解释断点。
- 账号管理的列表自动刷新与真实健康巡检已拆分。逐账号巡检必须由用户显式开启，每分钟最多探测当前页一个账号，并明确提示会产生少量调用。
- 桌面窗口使用 Windows 语义的自绘深色标题栏，保留最小化、最大化/还原、关闭、拖动和双击标题栏行为。
- 桌面开发服务器忽略 `src-tauri/target/**`，避免 Windows 在 Rust 替换调试 exe 时触发 Vite `EBUSY` 并阻止客户端窗口启动。

## 升级行为

- v0.2.18 客户端可以通过现有桌面自动更新通道直接升级到 v0.2.19，无需先卸载；手动运行 v0.2.19 NSIS 安装包同样会原位升级并保留本地配置。
- 桌面升级不再因为内置内核 SHA 或桌面提交变化而弹出“恢复内核”。
- 发现兼容内核后自动下载、校验并暂存，无需终端用户点击；在下一次安全启动时激活并执行健康检查。
- 如果官方内核版本高于当前兼容构建，界面只显示“兼容内核构建中”，不会自动降级，也不会安装缺少账本能力的官方二进制。
- 旧状态文件中缺少能力声明的内核不再显示算法版本，而显示“不可用（缺少账本能力）”。

## 数据与兼容性

- 账号成本损失账本继续使用追加式事件表和幂等键；本版本不删除或重写已有账本事件。
- 保留活动、待激活和上一版内核三个槽位；下载失败、能力验证失败或启动健康检查失败时保持/恢复原内核。
- 桌面版本和内核版本可独立更新，内核扩展版本单独比较，不依赖 SemVer 构建元数据排序。

## 验证结果

- UI 壳合同测试验证整个成本控制台强制使用深色语义角色、内容面不继承系统浅色配置，并验证数据治理不再占用一级导航。
- 实测颜色对比度：主文字/画布 `16.06:1`、次要文字/面板 `5.01:1`、荧光绿/画布 `13.06:1`、深色文字/荧光绿 `12.77:1`。
- 前端 TypeScript 类型检查与完整 Vitest 测试集通过；新增图表测试覆盖有效序列、真实空态和缺样断点。
- Go 回归测试覆盖 5 秒证据桶、自适应 Ops 桶、相邻稳定样本、成员变化重置和经济事件序列。
- Rust 桌面运行时测试覆盖稳定身份、能力门禁、禁止降级、独立版本比较、自动暂存和幂等下载。
- Vue 更新中心测试覆盖无误报、兼容构建等待、自动内核更新和恢复错误展示。
- Go 测试验证内核 `--version` 输出包含上游提交、扩展版本与能力集合。
- 发布流水线在生成安装包前验证内核身份，并为兼容内核 ZIP、更新清单和桌面安装包生成 SHA-256 校验文件。

## 回滚说明

- 新内核首次启动未通过健康检查时自动恢复上一版内核。
- 桌面更新与内核回滚相互独立；回滚桌面不会自动降级正在运行的更新内核。
- `core-stable` 发布失败时客户端继续使用当前已验证内核，不会回退到未经能力验证的官方二进制。
