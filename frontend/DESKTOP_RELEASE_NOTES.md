# Sub2API Cost Console v0.3.3

## 主要更新

- 修复 Windows 桌面更新时先启动安装器、未执行停止流程的问题。现在先下载，再停止内核和插件，最后启动安装器；安装失败会尝试恢复本地内核。
- 桌面或兼容内核版本变化后，已有插件自动进入正式停用状态，同时关闭全部路由绑定。安装文件、配置和作用域保留，检查兼容性后可重新启用，无需卸载重装。
- 插件导入遇到 `failure_mode` 等 v2 字段不被识别时，提示检查实际连接的兼容内核，保留签名和严格字段校验。
- 保留 Windows 原生一键启动、成本核算、发布者信任和独立内核更新。
- 修复旧密钥导致的插件配置认证失败：无法验证的旧密文会被清除，插件使用默认配置启动，管理员可以重新保存配置。

## 技术变更

- Windows updater 安装会退出桌面进程，停止步骤移至 install 之前；下载失败不会停止内核。
- 受管内核通过桌面持有的标准输入管道接收退出请求，执行 HTTP 排空和插件清理；超过等待期限后终止所属 Windows Job，并等待插件子进程退出。
- 恢复插件进程前比较桌面、内核和扩展版本。先持久化停用状态和绑定，再原子保存升级完成标记；失败会重试，并保留原有的失败关闭策略。
- 配置密文认证失败时，先清除不可恢复的密文再启动插件，防止配置解密错误把插件卡在启动阶段；清除失败会保留错误并阻断路由。
- 同版本普通重启保留用户重新启用的插件。独立服务器不使用桌面升级停用策略。

## 升级行为

- 从旧桌面升级的首次启动会停用已有插件，包括此前显示错误但仍有启用绑定的插件。管理员在插件管理中确认后重新启用即可。
- 程序内更新和下载 EXE 覆盖安装均由新内核首次启动处理旧插件状态。仅更新兼容内核也会触发一次停用。
- 自动停用不删除插件配置、安装包、发布者信任或路由作用域。
- 如果配置窗口提示 message authentication failed，关闭并重新打开配置页，确认默认配置已加载后点击保存并测试；插件包和其他设置会保留。
- 如果连接的是外部旧内核或上游原版服务，需要更新实际提供 API 的服务；仅更新桌面外壳无法使该服务识别本项目的 v2 插件。

## 验证结果

- 回归测试覆盖安装前停止顺序、下载/停止/安装失败恢复、升级后清除失效路由、同版本重启、内核/扩展更新、回退、数据库写入失败重试及服务器隔离。
- 保留真实插件进程、权限隔离和 fail_closed 测试；Windows 进程测试覆盖内核及其插件子进程退出。
- 发布流水线对发布提交执行后端、前端、桌面合同测试、构建及签名。

## 回滚说明

- 回退二进制不会恢复先前的启用绑定；插件配置和安装数据仍保留，需要重新启用。若旧配置密文无法验证，保存默认配置后会生成新的密文。
- 本次不增加数据库迁移。回退桌面前请备份数据库与 `%APPDATA%\com.sub2api.cost-console`。
- 下载并安装正式 Release 中的 Windows x64 安装器，更新签名继续使用既有公钥验证。
