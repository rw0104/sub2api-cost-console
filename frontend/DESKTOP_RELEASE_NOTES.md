# Sub2API Cost Console v0.3.25

## 主要更新

- 同步上游 Sub2API `v0.2.16`：新增 Gemini 显式上下文缓存（`/v1beta/cachedContents` 的创建、续期与存储计费）、Claude Haiku 5.5 价卡与长文本阶梯、临时不可调度规则的作用域控制，以及分组国际化字段。
- 修正 gemini-3.6-flash 的内置兜底价，补齐官方 priority 档（标准价 1.8 倍）。缺少该档时请求会落到通用服务层级的 2 倍倍率，在远程价目表不可用期间按 priority 计费会比官方价高约 11%。
- 修复关停时账号经济采样器没有停止的问题。采样协程此前会在 Redis 与数据库连接关闭之后继续取样。
- Windows 原生一键启动沿用 v0.3.24 的平台协议选择规则，本轮没有行为变化。

## 技术变更

- 上游与插件迁移同号共存：上游新增 `242_group_i18n` 与 `243`–`245_gemini_cached_contents*`，本仓库已发布的插件迁移占用 `242`–`247`。迁移执行器以完整文件名为主键、按字典序执行，没有版本水位，两边文件名都保持不变，不重新编号。
- 账号成本口径：长上下文附加费计入账号成本（`account_stats_cost`），与客户售价同源。渠道自定义账号统计定价仍按规则单价平价计算，不叠加官方附加费，这是既有设计。
- Gemini 显式缓存的存储费按官方价叠加，并在用量记录、实际扣费与账号成本归集三处只计一次。仅有存储费的续期记录不是一次模型请求，不写 `account_stats_cost`，由归集回落 `total_cost`。
- 临时不可调度规则的作用域与终态成本损失账本保持既有优先级：model-scope 的 401 只冷却模型、不写账本；凭据级 401 写账本并停用账号；402 工作区停用在规则判定之前处理。
- `/v1beta/cachedContents` 的 5 条路由与宿主插件管理路由注册在同一引擎上，启动期不冲突。

## 升级行为

- 可在“版本与更新”中升级，也可以退出程序后使用安装器原位升级；应用身份、数据库连接和已有业务配置保留。
- 首次启动会补跑上游新增的 4 个迁移，均为增量 DDL（新增列与新建表），已应用的插件迁移校验和不变；再次启动不会重复执行。
- 桌面、兼容内核或扩展版本变化后的首次启动会停用旧插件一次，保留配置、已签名原包、发布者信任及路由作用域；确认兼容后可重新启用。
- 兼容内核先于桌面安装器发布，校验版本、上游提交、扩展版本、能力清单和归档 SHA-256。
- 必需能力清单与 v0.3.24 相同，因此旧桌面也会自动拉取本轮内核。

## 验证结果

- 发布门禁要求同一源码提交通过完整后端 CI（unit、integration、golangci-lint）、前端测试与 lint、Rust 桌面测试和生产构建。
- 上游合并以 synthetic 基线方式进行，合成提交的目录树与上游 `v0.2.16` 标签逐字节一致，文本冲突为 0；`verify-core-source` 校验通过。
- 迁移升级路径在独立数据库上重建 v0.3.24 的迁移历史后验证：恰好补跑 4 个上游文件、插件迁移校验和不变、重启为空操作，另在空库完整执行一次。
- 计费口径定向回归：Haiku 5.5 的长文本阶梯在价目表与内置兜底两个来源下一致，超阈值请求的客户售价与账号成本同时计入附加费；gemini-3.6-flash 两源同价（含 priority 档）。
- Gemini 显式缓存存储费覆盖用量记录、扣费命令与账号成本归集三方，并验证只计一次。
- 限流与成本损失账本的交叉用例覆盖 model-scope 401、凭据级 401、402 工作区停用（普通与池模式）及快速路径入口。
- 回归确认 `/v1/responses` 降级到 chat completions 后，出站仍经过插件接缝，保护传输与请求头观测不会被绕过。

## 回滚说明

- 本轮上游迁移均为增量操作（新增列、新建表），旧内核会忽略多出的列和表，回滚是安全的。
- 可回退到桌面 v0.3.24 及匹配的内核 `v0.2.15` / 扩展 `1.3.16`，但会失去本轮的 Gemini 显式缓存、Haiku 5.5 价卡与兜底价修正。回退前建议备份数据库。
- 兼容内核不允许降级发布，也不允许同名包更换内容。出现问题时向前修复，发布 `0.2.16` + 扩展 `1.3.18`；客户端可使用本地回滚槽位回到上一个内核。
- Tauri updater 的 `.sig` 用于自动更新验签，不代表 Windows Authenticode 发行者签名。
