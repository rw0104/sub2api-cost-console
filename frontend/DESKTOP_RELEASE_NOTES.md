# Sub2API Cost Console v0.2.33

## 主要更新

### 启动失败说明与恢复

- Docker 未启动时明确显示原因和操作指引，原始错误日志收进“查看技术详情”。
- 启动内核前检查配置中的 PostgreSQL 与 Redis/Valkey；等待依赖期间不反复创建内核进程。
- Docker 就绪后，自动恢复已经存在且归属、端口均匹配的本产品数据容器，再继续启动内核。
- “重新检测并启动”会取消旧启动任务、停止旧内核并等待进程退出，然后重新检查依赖，无需退出整个应用。
- 高级连接继续使用配置中的服务地址；远程数据库或自建缓存不可用时给出对应提示。

### 重复进程与异常退出修复

- 桌面启用单实例保护，重复打开会唤回已有窗口。
- 并发启动只保留一个启动任务；旧进程日志、旧健康检查和延迟重启不能覆盖新一轮状态。
- Windows 使用进程监管任务清理受管内核，桌面异常退出时一并终止其内核进程。
- 对已有端口上的服务执行 Sub2API 健康检查，避免将普通 HTTP 服务误认为内核就绪。
- 依赖不可用时等待恢复，避免将 Docker 或数据库问题误判为新内核不兼容并回滚。

### Windows 原生一键启动

- 保留 ChatGPT Desktop、Codex CLI、Claude Code、Cursor Agent、OpenCode 和 Grok CLI 的原生启动能力。
- 继续保留成本损失账本、经济采样、成本真实性面板和本地配置。

## 技术变更

- 新增配置感知的数据服务检查，只使用已有容器的管理标记和端口映射验证归属，不重建数据库、不重置卷或密码。
- 启动预留、进程停止、重试和健康检查增加代次校验与并发控制。
- 引入 Tauri 单实例插件和 Windows Job Object 退出清理。
- 桌面发布工作流增加 Rust 生命周期测试、前端全量测试与 ESLint 门禁，覆盖仅更新桌面程序的发布。

## 升级行为

- 通过签名更新或 Windows x64 NSIS 安装包升级至 `v0.2.33`，保留已有配置和数据库。
- 本次修复位于桌面启动器，独立更新内核不足以修复该问题，需要更新桌面安装包。
- Docker 启动后仍需等待引擎和数据库容器就绪，应用会自动继续，也可手动点击“重新检测并启动”。
- 从内核 `v0.2.1` 升级时仍包含 `v0.2.2` 的模型白名单迁移：原模型列表配置会约束请求准入，名单外模型可能被拒绝。

## 验证结果

- 使用隔离配置在 `v0.2.2` 内核上复现数据库未启动的连接拒绝错误。
- 回归覆盖 Docker 关闭后恢复、已有容器恢复、远程服务失败、容器归属校验、旧任务失效、并发启动和页面内重试。
- Windows 真实子进程测试覆盖未监听端口时的停止等待与监管句柄关闭后的清理。
- 发布流程运行 Rust 和前端全量测试、ESLint、生产构建，再生成安装器、更新签名和 SHA-256 文件；详细结果见发布报告。

## 回滚说明

- 新内核确实无法启动时仍保留内核回滚路径；数据服务未就绪时等待恢复。
- 本次桌面修复不新增数据库迁移；退回旧桌面会失去新的启动恢复与单实例保护。
- `v0.2.2` 的数据库迁移不会随二进制回滚撤销，需要回退旧内核时应配合升级前备份。
