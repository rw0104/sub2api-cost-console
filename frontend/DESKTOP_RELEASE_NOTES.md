# Sub2API Cost Console v0.3.7

## v0.3.7 补充

- 桌面安装包同步上游 Sub2API v0.2.8，并保留宿主插件治理、账号探测、鉴权会话和持久化配置恢复能力。
- 修复成本中心价格目录状态和手动同步接口缺失导致的 404，价格目录失败时保留可用缓存并显示原因。

## 主要更新

- 紧急修复插件配置密钥没有持久化的问题。初始化后将 AES 密钥存入数据库，重启和升级继续复用，不再因缺少环境变量而每次换钥。
- 取消 v0.3.3 在配置读取、测试和保存出错时自动清空旧密文的行为。无法解密时保留原文并提示恢复。
- 已分享的原始 .s2plugin 包无需重新编译、签名或打包。宿主提供明确确认的重新配置入口，先备份旧密文再保存新配置，保存失败不修改原配置。
- 保留 Windows 原生一键启动、安装前停止内核/插件、成本功能和发布者信任。

## 技术变更

- 在创建加密器前完成数据库密钥初始化；并发实例通过唯一键和插入后回读获得同一个持久密钥。已配置的密钥首次入库；与已保存值冲突时拒绝悄悄替换。
- 读取、测试、启用和普通保存均不覆盖解密失败配置，也不会把空默认配置当作恢复成功。
- 新增管理员二次验证保护的配置恢复接口，要求插件已停用，并校验旧配置摘要和版本快照；备份与新配置写入在同一事务中完成。
- 数据库迁移 243 只增加加密配置备份表。不会重新打包插件或修改其清单、签名、能力与业务逻辑。

## 升级行为

- 已安装 v0.3.1 至 v0.3.6 的用户均可通过桌面更新升级到 v0.3.7；安装包内置上游 v0.2.8，自动内核通道提供同一版本和扩展 1.3.3。
- 升级后插件会停用一次，原包和可读配置保留。确认配置后重新启用；同版本普通重启保留启用状态。
- 旧密钥已丢失时，先停用插件，在配置页重新填写设置，勾选“备份旧密文后替换”并保存，再启用。使用原来的分享包即可，无需作者再打包。
- v0.3.3 已经清空的配置无法自动还原，需要重新填写一次；持久密钥确保此后重启继续可读。
- 如果有原始密钥/数据库备份，应优先恢复匹配的备份。不要通过更换随机密钥尝试解密旧数据。
- 本地内核以外的独立服务需要更新实际宿主；更新桌面外壳不会更新外部服务器。

## 验证结果

- 使用真实 AES 复现旧版重启后的 message authentication failed，验证持久化后同一配置跨启动可解密。
- 回归覆盖并发密钥初始化、显式密钥保留与冲突、无效存储密钥、旧密文只读保留、恢复确认及过期确认隔离。
- 集成验证覆盖原签名包、配置保存、升级后重新启用、普通重启、旧密文备份、新配置验证失败和数据库事务回滚。
- 发布流水线执行后端、前端、桌面生命周期与 SDK 检查，并使用既有 updater 公钥对应的密钥签名。

## 回滚说明

- 本次恢复操作会保留旧密文备份，但密钥缺失的历史数据和此前已被清空的配置无法凭空恢复。
- 回退到旧程序可能重新启用临时密钥逻辑或自动清空配置逻辑，不建议用旧版处理新保存的配置。
- 备份应包含完整数据库（含 security_secrets）及配置目录。恢复时不要混用不同数据库对应的加密密钥。
