# 桌面端 UI 主题与导航热修复（v0.2.19）

## 问题

v0.2.18 将 Apple 语义样式接入成本控制台后，内容面颜色仍由 `prefers-color-scheme` 决定。Windows 使用浅色外观时，`data-aui-layer="content"` 会获得白色内容面和深色标签变量，而成本卡片仍保持深色，最终形成白色外层、深色卡片和近黑文字混合的不可读界面。

这不是数据或图表算法问题，而是主题边界缺失与 CSS 语义变量继承错误。之前仅验证类型、单元测试和构建结果，没有验证正式桌面包在 Windows 浅色外观下的实际组合状态，因此未能拦截该回归。

## 修复

- 成本控制台根节点增加显式 `data-aui-appearance="dark"`。
- 在根节点统一映射 Apple 语义角色：画布、内容面、次级内容面、主/次/三级文字、分隔线、填充、焦点和功能材质均使用原有 Sub2API 深色/荧光绿体系。
- 内容区显式恢复深色网格画布，阻止全局浅色内容面覆盖。
- 该边界覆盖资产总览、上游排行、渠道号池、数据治理、API 接入和成本档案弹层，不对各页面逐一写临时颜色补丁。
- 一级工作区导航移除“数据治理”；入口保留在右上角工具区。一级导航改为资产总览、上游排行、渠道号池、API 接入，对应 `Ctrl/Cmd + 1…4`。

## 回归门禁

- 校验成本根节点必须声明深色语义边界。
- 校验 Apple 画布、内容面和标签角色必须映射到成本主题变量。
- 校验主文字/画布、次要文字/面板、荧光绿/画布、深色文字/荧光绿的对比度。
- 校验数据治理不得再次进入一级导航，同时必须保留右上角入口。
- 版本提升为桌面端 v0.2.19；成本算法仍为 v1.6.0，Token 输入/输出/缓存计费公式及模型价格没有变化。

## 发布验证

有效的最终验证对象是 Tauri release 构建生成的 NSIS 安装包及 CI 签名更新产物。旧 debug 可执行文件连接 Vite 的结果不作为正式客户端验证证据。
