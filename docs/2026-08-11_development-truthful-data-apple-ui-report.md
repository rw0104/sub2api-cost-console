# 成本中心真实数据与 Apple UI 修复报告

本次修复让成本中心明确区分“真实的 0”“当前范围无记录”“来源读取失败”“估算值”“部分数据”和“预测样本不足”，并修复经济总成本重复计入封禁净损失的问题。

> 重要边界：本次没有修改 Sub2API 的 Token 输入、输出、缓存计费公式、模型价格或账号倍率。成本算法仍显示 `1.6.0`；1.6 表示监控与经济聚合语义升级，不是 Token 调价。本次是在 1.6 上修复统计正确性与展示可信度。

## 使用与验收

打开成本中心后，可通过顶部“数据治理”工作区检查所有成本中心数据源。每个来源只能处于以下状态之一：

| 状态 | 含义 | 数字展示 |
| --- | --- | --- |
| 实测 | 来源读取成功且存在记录 | 显示真实数字，包括真实的 0 |
| 无记录 | 来源读取成功，但当前范围没有记录 | 显示“无记录”，不冒充接口失败 |
| 估算 | 使用汇率回退、默认套餐或明确推导值 | 显示数字并标注“估算” |
| 部分可用 | 只有部分范围、兼容聚合或事实可用但预测不足 | 显示可证明部分，并说明缺口 |
| 旧数据 | 本轮没有更新，保留最近一次成功结果 | 标注“旧数据” |
| 不可用 | 请求失败或依赖来源不可用 | 显示“无数据”和失败原因 |
| 读取中 | 正在刷新 | 不提前显示 0 |

时间口径保持以下边界：

- “当天”是本机时区的自然日，从 00:00 起算；跨日后当天请求、Token 和用量金额自然归零。
- “最近 24 小时”是滚动窗口，与“当天”不是同一口径。
- 采购累计从账号成本档案的起算时间累计，不做每日清零。
- 封禁损失、退款和冲销属于不可变事实账本，不随日期或账号删除清零。
- 经济样本属于可再生预测数据，自动保留 90 天；成员变化或累计值倒退会重置预测基线。

## 修复内容

### 修复经济总成本重复计算

问题证据来自截图中的关系：`¥340.91 ≈ ¥172.54 + ¥168.37`。后端的 `recognized_cost` 已等于 `accrued_cost + net_loss`，但经济聚合又把 `recognized_cost` 和 `net_loss` 相加，导致净损失被计算两次。

修复后的公式为：

```text
经济总成本 CNY = 实际累计采购成本 CNY + 封禁净损失 CNY
```

实现位于 `backend/internal/service/account_economics.go`。回归测试使用截图同量级数据验证：采购 `4.17`、净损失 `168.37`，经济总成本必须为 `172.54`，不能是 `340.91`。

### 阻止“接口失败 = 0”

`frontend/src/features/cost-center/dataState.ts` 定义统一数据状态。`useCostCenterData.ts` 现在分别记录账号、损失账本、usage 趋势、当日账号统计、用量窗口、模型统计、路由审计、价格目录、Ops、设置、汇率和经济采样的读取结果。

主要行为变化：

- 批量当日统计失败时，账号表显示“无数据”和原因，不再显示 `$0 / 0 请求 / 0 Token`。
- 成本趋势失败时，图表显示来源状态，不再画一条看似真实的零线。
- 模型快照失败时，只在完整 `usage_logs` 兼容聚合成功后显示“部分可用”；否则显示“无数据”。
- 损失账本失败时，经济成本和采购费率不再仅用现存账号拼出一个不完整数字。
- API Key 读取失败时显示“密钥接口读取失败”；只有请求成功且清单为空时才显示“当前确实没有密钥”。
- K12 或套餐默认成本继续允许作为估算，但“经济数据完整度”会显示“采购成本含默认估算”，不能显示“完整”。
- 稳定区间不足时显示“事实可用 · 预测待样本”，不把预测 `null` 格式化为 0。

### 覆盖全部成本中心展示面

| 展示面 | 已处理的数据族 |
| --- | --- |
| 资产总览 | 账号、采购、损失、当日成本、窗口产出、月度预测、可用账号 |
| 全部图表 | usage 趋势、综合成本、请求量、号池产出、采购费率 |
| 模型成本 | 模型统计、价格目录、毛利、缺价与历史回退 |
| 模型路由审计 | 观测数、一致/替换、请求快照、截断状态 |
| 上游账号表 | 用量窗口、今日成本/产出/请求、成本档案、运行状态 |
| 渠道号池 | 事实成本、预测速率、完整度、健康数量、分组统计 |
| API 接入 | API Key 列表、连接测试、模型列表与延迟诊断 |
| 数据治理 | 来源状态、时间口径、保留策略和历史维护入口 |

“号池运行状态”现在使用“可调度”而不是“正常”描述后端运行字段。没有执行本次会话主动探测的账号会计入“未主动探测”，整项标记为“部分可用”，避免把未验证的 402/429 上游连接宣称为实时正常。

### 增加历史数据控制面板

新的“数据治理”工作区提供：

- 全部来源刷新；
- 每个来源的状态、原因和最近更新时间；
- 自然日、滚动窗口、生命周期累计和 90 天样本保留说明；
- 当前经济样本数、稳定区间数和预测置信度；
- 跳转现有 `/admin/usage` 历史记录与清理任务的安全入口。

面板没有提供模糊的“一键清零”。`usage_logs` 使用已有可审计清理任务；经济样本由 90 天保留策略自动维护；损失账本不允许从该面板删除。

## Apple UI 实现

本次使用 Apple 的内容/功能分层原则优化成本中心，而不是模仿 macOS 窗口外壳：

- 顶部工具栏是唯一 Regular 功能材质层；表格、图表和财务卡片保持不透明。
- 窗口、导航、工具栏、内容区和检查器具有明确的自适应语义。
- 指针按压、焦点、滚动边缘、减少动态效果、减少透明度、增强对比度和强制颜色由编译后的 Apple fidelity runtime 处理。
- 状态不能只靠颜色表达，同时包含图标、文本标签和原因。
- 紧凑窗口重排导航与摘要，但不丢失当前工作区和筛选条件。

设计证据和决策记录在 `frontend/.apple-ui/design-brief.json` 与 `frontend/.apple-ui/visual-system.json`，编译产物位于 `frontend/src/apple-ui/`。

## Evidence → Finding → Path

| Evidence | Finding | Path |
| --- | --- | --- |
| 截图中的经济总成本接近“已确认成本 + 净损失” | 净损失被重复计入 | `account_economics.go` 改用 `AccruedCost + NetLoss`，并增加固定数值回归测试 |
| `emptyTodayStats()` 在批量接口失败后仍返回全 0 | 失败和真实零无法区分 | `dataState.ts` + `useCostCenterData.ts` 返回可空账号统计和独立来源状态 |
| 图表输入失败时仍收到空数组或补零数组 | 零线可能被误认为没有流量 | `CostLineChart.vue` 增加 loading/empty/unavailable 状态面板 |
| 经济接口只按成本档案和汇率判断“完整” | 默认套餐、零产出和预测不足被隐藏 | `CostCenterView.vue` 合并成本来源、默认成本和预测置信度生成展示状态 |
| API Key 请求使用 `Promise.allSettled`，失败后仍保留空数组 | 读取失败显示成“没有密钥” | `CostApiAccessPanel.vue` 增加 loading/measured/empty/unavailable 状态 |
| 历史语义散落在 usage 清理页和后端保留策略 | 操作者不知道哪些数据可清理、哪些不可清零 | `DataGovernancePanel.vue` 集中展示口径并链接已有清理任务 |

- 成本中心 16 个测试文件、123 项测试通过；其中确定性组件测试分别覆盖实测零值、成功空查询、接口失败、API Key 读取失败/真实空清单、估算值和治理面板；

桌面窗口可启动，但开发源的登录存储域与正式客户端隔离。不得通过复用正式客户端会话或临时替换活动核心来“证明”开发 UI 正确。本次改用不依赖登录态的确定性数据夹具完成自动回归；真实数据端到端验收必须由操作者在独立测试客户端完成登录后执行，本文档不将未完成的认证验收写成“已通过”。
