# 上游响应模型审计与成本归因

本文记录桌面端随 Sub2API `v0.1.172` 引入的上游响应模型审计、成本统计口径、数据库迁移和验收边界。该能力用于区分本站模型映射与上游中转站自行替换或降级模型的行为。

## 1. 三种模型身份

每次请求最多包含三种不同的模型身份：

| 身份 | 字段 | 含义 | 用途 |
| --- | --- | --- | --- |
| 用户请求模型 | `requested_model`，旧记录回退 `model` | 客户端最初提交的模型 | 分析用户意图 |
| 实际发往上游模型 | `upstream_model`，缺失时回退请求模型 | 经过本站/渠道映射后真正发送给上游的模型 | 请求时定价、渠道匹配和路由分析 |
| 上游响应声明模型 | `upstream_response_model` | 上游响应体或流事件自报的模型 | 审计上游是否替换模型 |

`upstream_model_mismatch` 是三态字段：

- `false`：响应声明模型与实际发往上游模型一致。
- `true`：两者不一致，可能发生上游替换或降级。
- `NULL`：旧日志，或该响应没有提供可审计的模型；不得当成“一致”。

本站在发出请求前完成的模型映射不算上游替换。例如 `deepseek-chat → deepseek-v4-pro` 会记录在 `model_mapping_chain`；只有上游随后声明了另一个模型时才标记不一致。

## 2. 成本归因规则

模型审计不会回写或重新计算历史金额。请求结束时写入的以下快照仍是结算依据：

- `total_cost`：请求发生时的标准价或渠道价成本。
- `account_stats_cost`：请求发生时按账号费率计算的上游账号成本。
- `actual_cost`：用户实际计费。
- Token、渠道、账号、端点和模型映射快照。

选择“上游响应声明模型”只会改变汇总分组维度，不会用上游自报名称重新查今天的价格。因此，中转站错误声明、恶意伪报或后续价格目录更新都不能篡改历史成本。

当前算法版本 `1.4.0` 的模型维度为：

```text
requested = COALESCE(NULLIF(TRIM(requested_model), ''), model)
sent      = COALESCE(NULLIF(TRIM(upstream_model), ''), model)
response  = COALESCE(NULLIF(TRIM(upstream_response_model), ''), sent)
mapping   = requested || ' -> ' || sent
```

响应字段缺失时，“响应声明模型”汇总会回退到实际发往上游模型用于保持旧日志可见；同时审计状态仍为“未观测”，不会伪装成已验证一致。

## 3. 历史模型与当前账号池

“模型成本分析”展示所选时间窗口内的真实调用历史，不是当前账号池的模型清单。当前只剩 DeepSeek 账号时仍可能看到 GPT，原因是窗口内此前确实有 GPT 请求，或已删除账号仍有保留的历史日志。

- 一天内调用多个模型时分别成行，不会被当前模型覆盖。
- 表格显示首次和最近调用时间。
- 可按时间窗口和具体成本账号筛选。
- “仅看不一致”只保留 `upstream_model_mismatch = true` 的请求。
- 删除账号不会删除历史 `usage_logs`；路由表会标记“已删除账号（历史）”。

界面同时展示审计已观测、一致、不一致、未观测、不一致率和不一致请求的成本暴露。分母只包含已观测请求，避免把旧日志 `NULL` 误算为一致。

## 4. 数据库与 API

升级会执行：

- `194_add_usage_log_upstream_response_model.sql`：新增响应模型和三态审计字段。
- `195_add_usage_log_upstream_model_mismatch_index_notx.sql`：为不一致筛选增加并发索引。
- `194_preserve_usage_logs_when_accounts_deleted.sql`：本项目已有迁移，允许账号删除后保留用量历史。

迁移运行器按完整文件名记录执行状态；两个 `194_` 文件名称不同，均会执行且不会互相覆盖。

Dashboard 的 `model_source` 支持：

```text
requested | upstream | response | mapping
```

用量列表、趋势、模型、分组和 Dashboard Snapshot 支持：

```text
upstream_model_mismatch=true|false
```

## 5. 协议覆盖与限制

Sub2API `v0.1.172` 会在支持的普通响应、流式响应、兼容转发和 WebSocket 路径提取上游响应模型。若某个供应商或中转站不返回模型字段，该条记录保持“未观测”。

审计能证明“上游声明了什么”，不能仅凭声明证明实际执行的权重或硬件。对高风险中转站仍应结合输出质量、延迟、价格异常、错误率和供应商账单审计。

## 6. 验收清单

1. 请求模型、发往上游模型、响应声明模型在用量详情中均可查看。
2. 一致响应写入 `false`，不一致响应写入 `true`，无声明响应保持 `NULL`。
3. Dashboard 的四种模型口径分别聚合，时间和账号过滤保持生效。
4. “仅看不一致”同时影响模型汇总和真实路由明细。
5. 切换为响应模型口径时，三类历史金额与请求快照保持不变。
6. 当前池只剩 DeepSeek 时，历史 GPT 仍按所选窗口显示，并有首次/最近时间和历史账号标记。
7. 升级真实旧数据库后，两项新迁移成功，旧日志为未观测，历史用量未丢失。
8. 桌面整包升级后，若活动内核与内置 `v0.1.172` 内核的版本、提交或 SHA-256 不同，版本面板明确要求恢复或保留；恢复失败自动回滚。
