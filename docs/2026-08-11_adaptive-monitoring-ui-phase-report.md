# 成本监控 1.6：自适应图表、账号巡检与桌面 UI 开发记录

日期：2026-08-11
分支：`codex/cost-economics-1.6`

## 1. 本阶段结论

本阶段升级的是“监控、采样与聚合语义”，不是 Sub2API Token 调价。

- 成本算法仍为 `v1.6.0`。
- 经济预测与时间序列版本由 `v1.0.0` 升为 `v1.1.0`。
- Sub2API 输入 Token、输出 Token、缓存写入、缓存读取计费公式没有修改。
- 模型价格目录、账号倍率快照和采购摊销公式没有修改。
- `account_economics_sampling.v1` 仍是桌面核心升级门禁要求。

## 2. 四项需求的实施结果

### 2.1 自适应采样和丰富曲线

Ops 聚合按照观察窗口选择桶宽：

| 窗口 | 桶宽 | 目标点数 |
| --- | ---: | ---: |
| 1 分钟 | 5 秒 | 12 |
| 5 分钟 | 15 秒 | 20 |
| 30 分钟 | 1 分钟 | 30 |
| 1 小时 | 1 分钟 | 60 |
| 6 小时 | 5 分钟 | 72 |
| 24 小时 | 15 分钟 | 96 |
| 7 天 | 2 小时 | 84 |
| 30 天 | 6 小时 | 120 |

新增或补齐的数据序列：

- 经营：用户计费、上游账号成本、贡献毛利，统一按 CNY/小时展示；可切换查看每 1 USD 产出的固定采购成本、固定采购回本率和扣除采购后的贡献毛利率。
- 请求质量：成功、失败、切号，以及 429、402、其他上游错误。
- 账号健康：可调度、限流、错误账号数量；“未验证”不从正常状态反推，必须等待可持久化的巡检证据后再加入历史曲线。
- 延迟：TTFT P50、TTFT P95、请求总耗时 P95。
- Token：输入、输出、缓存写入、缓存读取占比。
- 模型贡献：收入、上游成本、毛利 Top 8，固定三项指标。

单张折线图最多接收三条序列；其他指标通过原生选择控件切换。估算采购基线继续使用虚线，延迟缺样使用 `null` 断点，不转换成 0。

经济样本的唯一桶由 1 分钟改为 5 秒：后台常驻采样仍保持每分钟一次，避免空闲时制造高写入量；成本监控刷新和真实状态事件可保留 5 秒级证据。短窗口如果实际没有足够密度会显示断点，不会把一分钟样本复制成十二个假点。

### 2.2 Sub2API 设置与返回成本监控

- 成本监控顶部工作区新增“Sub2API 设置”按钮，进入 `/admin/settings`。
- 桌面客户端中的 Sub2API 侧边栏将“成本作战台”显示为“返回成本监控”，并使用明确的返回箭头图标。
- Web 管理后台继续保留原来的“成本作战台”名称，避免改变非桌面端的信息架构。

### 2.3 单账号状态自动监控

排查确认，原账号页“自动刷新”只执行：

- ETag 账号列表增量读取；
- 今日统计刷新；
- 最近用量显示同步。

它原来不会逐账号发送健康请求，因此低流量账号的 402/429 只能依赖实际业务请求或手动测试更新。

本阶段新增独立开关“逐账号健康巡检”：

- 必须由用户显式开启；
- 每分钟最多真实探测当前页一个活动、可调度账号；
- 轮询当前页，避免一次并发测试大量账号；
- 界面明确提示会产生少量调用；
- 探测错误不会被显示成正常，后续列表刷新读取内核持久化的 402/429/错误状态。

API Key 上游倍率自动探测是另一套已有后台任务，只作用于显式启用的 API Key，不能代替 OAuth/K12 健康巡检。

本次真实探测会让核心现有的 429/402 处理逻辑更新限流或终态错误，因而后续账号列表与经济样本不再继续把这些账号计为正常。当前核心还没有通用的“最后一次健康探测”不可变账本，所以没有把“未验证账号数”伪造成历史曲线；这项数据仍需后续事件账本才能可靠补齐。

### 2.4 桌面窗口边框

Tauri 主窗口改为无系统装饰窗口，并新增应用自绘深色标题栏：

- 支持拖动窗口；
- 双击标题栏最大化/还原；
- 保留 Windows 风格的最小化、最大化/还原、关闭按钮；
- 关闭按钮使用 Windows 危险操作反馈；
- 外框、标题栏和成本监控深色视觉连续，不再出现截图中的白色系统边框。

没有仿造 macOS 红黄绿按钮；Apple UI 规范只用于层级、材质范围、状态表达和控件密度，窗口行为仍遵循 Windows。

真实 `tauri dev` 首次启动还暴露了一个 Windows 专属问题：Vite 会监听 Rust 正在替换的 `src-tauri/target/debug/*.exe`，从而以 `EBUSY` 退出。开发服务器现已明确忽略 `src-tauri/target/**`；修复后 0.2.18 客户端能够进入原生窗口事件循环。

## 3. 后端接口与算法变化

`OpsThroughputTrendPoint` 新增：

- `success_count`、`error_count`、`switch_count`；
- 输入、输出、缓存写入、缓存读取 Token；
- `user_billed_usd`、`account_cost_usd`、`contribution_usd`；
- `duration_p95_ms`、`ttft_p50_ms`、`ttft_p95_ms`。

`OpsErrorTrendPoint` 新增 `upstream_402_count`。

经济采样快照新增：

- `series`：自适应降采样后的账号健康与稳定区间速率；
- `events`：可证明的核心启动、账号池成员变化、累计值倒退、采样中断和封禁核销。

成员变化或累计值倒退的区间不会参与速率，返回空值并显示断点。

## 4. 真实展示规则

- 查询完整且桶内没有记录时可以显示 0。
- 接口失败时整张图显示不可用原因。
- 部分来源使用斜纹状态层和“部分数据”标记。
- 延迟字段没有样本时返回并渲染空值，不伪造 0ms。
- 旧 dashboard 端点无法提供自适应子分钟桶时保留其原生桶，不拆成虚假 5 秒零值；高密度曲线优先使用新版 Ops 聚合。
- 所有收入和上游成本仍读取 `usage_logs` 的事实字段与请求时价格快照。

## 5. 事件覆盖边界

当前已经能可靠显示：账号池成员变化、累计值倒退、采样中断、核心启动、封禁损失核销。

“具体是哪个账号加入/删除”和“成本档案具体字段何时变更”目前没有独立、不可变的经济事件账本。当前版本不会从 `updated_at` 猜测事件。后续如需精确审计，应新增专用事件表，并在账号创建、删除和成本档案变更事务内写入，而不是仅在前端保存临时标记。

## 6. 验证方法

本阶段使用不依赖正式登录态的确定性验证：

- Go 单元测试验证自适应桶选择、经济序列稳定区间和成员重置事件。
- Vue 单元测试验证 5 分钟窗口使用 15 秒桶、窗口外数据被排除、无时区 bucket 按 UTC 解释。
- TypeScript 类型检查验证新增接口与所有图表消费者。
- Rust 测试和 Tauri 配置编译验证窗口控制权限。
- 桌面 WebView 正式模式构建验证 Vue 产物；Rust 测试负责验证 Tauri 窗口配置与能力权限。本地不生成缺少更新签名的伪正式安装包；`v0.2.18` 标签由仓库 `desktop-release.yml` 使用 GitHub Secrets 中的 Tauri 私钥生成签名 NSIS、更新签名、`latest.json` 与 SHA-256 校验文件。
- 实际启动 0.2.18 Tauri 调试客户端，确认深色自绘标题栏、细外框和 Windows 三个窗口控制按钮已渲染。该调试 WebView 没有管理员登录态，因此没有把登录后的成本页截图冒充运行时数据验收。

正式账号的 402/429 仍需要用户在隔离测试客户端中显式开启巡检后观察；开发验证不复用用户正式客户端登录存储，也不以肉眼等待作为回归测试。

## 7. 后续建议

下一阶段优先新增不可变 `account_economics_events` 账本，补齐账号 ID 级加入/删除、成本档案 diff 和手动核算操作；随后再评估按账号或模型下钻的独立图表，而不是继续在总览堆叠更多折线。
